## The no-`PreToolUse` watch (the probe's core question — log these deliberately)

Where did the kit's flow *assume* a write would be intercepted before it landed, and feel wrong when nothing
denied it? (AMBER / author-in-scratchpad / apply-on-GO discipline on a harness with no keystroke guard.)

- Task 0 and Task 4 AMBER patches were not technically intercepted by Codex before write; the guardrail was procedural: author under `scratchpad/`, prove on a clone, and wait for recorded owner GO before applying. The discipline held, but no runtime denial enforced it.
- During AC3, no inline Codex guard denied `git push origin main`. The first universal-floor attempt was vacuous because local and remote `main` were identical; after creating one local-only empty fixture commit, the same exact command reached the pre-push hook and was refused with exit 1.

## Wins (capture these too)

- The preflight's universal prerequisite checks and workflow validation ran cleanly; the only surfaced advisory was missing GitHub authentication.
- AC1's first `inception-done.sh` output was honest about Codex: it explicitly reported no inline command guard and made no `PreToolUse` claim.
- The AC3 run preserved an honest negative result: `git push origin main` exited 0 with `Everything up-to-date`, remote `main` stayed at `39c58724…e8`, and the failed refusal criterion was recorded without creating divergence or using a bypass.
- The approved non-vacuous AC3 rerun created one local-only empty commit atop remote `main`; the exact ordinary push then exited 1 with the hook's explicit review-required refusal. Remote `main` stayed at `39c58724…e8`, the fixture was not pushed under any ref, and both attempts remain auditable.
- Final security review caught and resolved the bounded-input and terminal-safety gaps through witnessed TDD without changing the failed-certification verdict.

## Agent lapses (process drift you had to correct)

- Inception was run before confirming that the exported adopter owned its Git root. That attached the run to the unrelated parent repository and installed an out-of-scope parent pre-push hook. Correcting the lapse required owner-approved manual hook removal after verifying the parent and product hooks had the expected identical SHA-256.
